# 自动战斗方案

自动战斗方案（Auto Battle Profile）是一份可复用的战斗决策策略。它**只描述决策**，不绑定具体队伍；战斗任务通过项目引用方案，运行开始时由后端解析成快照。方案全局共享，编队分享码不携带方案——两者是独立功能。

## 数据与存储

- 持久化：`app_data_dir()/auto_battle_profiles.json`。
- 内置方案 `builtin-basic`（名称「基础方案」）在读取时自动补种，可编辑策略、不可删除，可用「恢复默认」还原。
- 项目字段（`projects.json`）：
  - `autoBattleTakeover: bool`：手动指令用完后是否交给自动战斗。
  - `autoBattleProfileId: string | null`：引用的方案 id；`null` 表示基础方案，引用失效时运行开始回退基础方案并告警。
- 运行配置（`RunConfig`）：`autoBattleTakeover`、`autoBattleProfileId` 透传给后端；运行开始时解析并快照，运行中改方案不影响当前运行。
- 编队分享码的 `LOCAL_FIELDS` 明确排除这两个字段：接管开关与方案属于本机运行偏好，不进分享码。

命令：

| 命令 | 说明 |
| --- | --- |
| `list_auto_battle_profiles` | 列出方案，内置方案置顶，其余按最近编辑排序 |
| `create_auto_battle_profile` | 新建方案（默认策略） |
| `duplicate_auto_battle_profile` | 复制方案（复制策略，新 id） |
| `save_auto_battle_profile` | 新增或更新；内置方案只允许改策略 |
| `delete_auto_battle_profile` | 删除；内置方案拒绝 |
| `reset_auto_battle_profile` | 仅基础方案：恢复默认 |

## 接管语义

「手动配置用完」= 当前 `(Battle 场次, 回合)` 没有可用的手动配置，包含：

1. 当前回合超出该场次配置的 `turns[]`（原行为是复用最后一回合的出卡配置）；
2. 当前场次在 `battle_scenes.json` 中未配置；
3. 项目完全没有指令配置。

规则：

- 接管后本次战斗不回退；每次重新进入战斗从第 1 回合重新判定。
- 接管在 Battle 画面分流：技能在 Battle 分支执行，出卡在 Attack 分支选择，不改画面识别与路由。
- 高级 / 冠位模式首版不接管，避免与冠位出卡策略叠加；后续作为策略扩展接入。

## 策略维度

| 维度 | 选项 | 基础方案默认 | 依赖 |
| --- | --- | --- | --- |
| 技能使用 | 全部 / 仅冷却好 / 仅指定 `(从者槽位, 技能槽位)` / 关闭 | 仅冷却好 | 技能按钮固定坐标；冷却识别 |
| 技能顺序 | 按从者（1 号位 1→3） / 按技能（技能 1 全员） | 按从者 | — |
| 御主礼装技能 | 包含 / 不包含 | 不包含 | 固定坐标（换人需两个目标，默认不开） |
| 技能目标 | 技能所属从者自己 / 最左前排 / 指定槽位 / 探测兜底 | 自己 | 目标选择框可探测 |
| 宝具使用 | 就绪即用（上限 1–3） / 每回合 1 张 / 只作第三张 / 关闭 | 就绪即用 3 张 | 宝具就绪识别 |
| 卡色选择 | 三同色优先（颜色顺序可配） / 三色各一 / 左到右 | 三同色（红→蓝→绿） | 卡面颜色识别 |
| 目标选择 | 不选（游戏默认） / 最左敌人 / 指定敌人 1–6 | 不选 | 敌人坐标 |
| 失败策略 | 跳过该步继续 / 停止运行 | 跳过该步 | — |

### 冷却识别

技能图标冷却时带有黑色半透明遮罩与剩余回合数。计划在 CV 侧新增「技能就绪」探针：按固定技能按钮区域采样遮罩亮度（必要时辅以数字区域），返回每个技能位是否可点。

- `readyOnly` 语义：只点就绪技能；**识别不可用时按「就绪」处理并照常尝试**，因此探针缺失只会退化为 `all`，不会漏放技能。
- 自动模式必须把「点了没反应」降级为跳过，不能走整次运行失败路径；等待窗口应短于手动模式覆盖技能动画的 15 秒。

### 刻意不提供的选项

以下选项需要当前侧车无法提供的信息，首版不放进配置页，避免出现「配了不生效」的死控件：

- 按技能类型（充能 / 增伤 / 无敌）开技能——需要从者身份与技能元数据。
- 按敌方血量 / buff 状态选目标——需要新增敌方状态识别。
- 按职阶克制选卡——需要敌方职阶识别。

## 后续接入

其他战斗任务（推主线、幕间物语、进阶关卡、活动关卡等）只需复用 `buildProjectRunConfig` 生成运行配置，并让 `Runner` 在「无手动配置」分支进入同一接管入口；无需新增协议。

## 界面入口

- 主页 → 战斗 → `03 自动战斗`：方案列表与策略编辑器（新建 / 复制 / 删除 / 恢复默认 / 保存）。
- 编队 → 指令设置顶部：`自动战斗接管` 开关与方案选择，随项目保存；强化任务复用同一项目配置，自动继承。
- 功能开关：`VITE_FEATURE_AUTO_BATTLE`（默认开）。
- 浏览器开发预览（无 Tauri 运行时）由 `devMock` 提供同形状的内存方案。

## 运行行为

启用接管后，普通模式在当前回合没有手动指令时由自动战斗驱动，详见[战斗自动化的接管章节](state-machines/battle-automation.md#自动战斗接管)。要点：

- 技能每个 `(场次, 回合)` 只执行一次；点击后 700ms 内出现确认弹窗 / 目标框 / 菜单消失即视为生效，否则跳过。
- 宝具按方案就绪即用（默认上限 3）；宝具占用的卡位不会被当作普通卡重复点击。
- 出卡优先三同色（颜色顺序可配），凑不齐时取数量最多的颜色，再左到右补齐。
- 敌方目标在攻击前选择；失败默认跳过该步。

技能冷却识别：

- 「只放冷却好的」每回合用一次**纯识别批量**（9 位约 890ms）：数字整段是纯数字，且左侧「剩余/残り」文字命中，才判冷却并跳过。这样图标箭头被误读成数字不会误跳。识别不可用时退回逐个尝试。
- 技能动画开始后点击右上角回合数/跳过区域一次、间隔 1 秒再点一次，加快技能动画；目标选择类技能在选定目标后同样处理。
- 御主礼装技能每回合只开一次面板，一次批量识别 3 个右下角；只使用未冷却的，冷却的直接跳过。用一个技能后面板会关闭，下一个就绪技能再重新打开面板（不需要为冷却技能反复开关）。
- 低星从者技能不足 3 个（或技能未解锁）时，自动战斗每回合先跑一次**技能位存在性检测**：扫描技能按钮顶部白边那一行，近白占比低于阈值（默认 0.95；实测真实技能位 1.00，空位 0.07–0.20）视为空位并跳过。检测不可用时退回全部尝试。
- 预检漏掉的空位如果被点中，会打开从者状态弹层；技能后 HUD 消失时自动识别右上角关闭按钮并点击，等战斗 HUD 恢复后继续，不会卡死。
- 御主礼装技能默认不在基础方案中（换人等双目标技能无法自动确定目标）；在方案里打开后按从者技能之后执行，无法确定的弹窗会被关闭。
- 高级 / 冠位模式不接管。
